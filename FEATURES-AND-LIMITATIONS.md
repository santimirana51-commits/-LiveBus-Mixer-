## Technical Audit & Solusi Masalah v0.4 Awal

1. **Bug Kompilasi Missing DSP Module**:
   - *Masalah awal*: `juce::dsp` tidak di-link pada `CMakeLists.txt` sehingga menimbulkan error kompilator `error C2039: 'dsp': is not a member of 'juce'`.
   - *Solusi*: Menambahkan `juce::juce_dsp` ke `target_link_libraries`.
2. **Bug Panning & Input Channel Mono/Stereo**:
   - *Masalah awal*: Kode awal v0.4 menugaskan `side = (i % 2 == 0) ? 0 : 1`, yang menyebabkan Input 1 (Mic) hanya keluar di speaker kiri, dan Input 2 (Guitar) hanya keluar di speaker kanan.
   - *Solusi*: Mengimplementasikan -3dB equal power pan law (`cos(theta)` dan `sin(theta)`) sehingga mikrofon dan instrumen dapat dipusatkan atau di-pan secara presisi ke stereo field.
3. **Bug Shared DSP State**:
   - *Masalah awal*: Mengubah parameter EQ/Compressor mengubah kedua bus secara bersamaan.
   - *Solusi*: Mengisolasi `BusDSPProcessor` dan `BusDSPParameters` terpisah untuk Stream Bus dan Monitor Bus.
4. **Data Race pada Audio Thread**:
   - *Masalah awal*: `applyDSPControls` mengganti reference-counted `Coefficients` langsung saat audio thread sedang memproses audio.
   - *Solusi*: Nilai koefisien diperbarui dengan aman atau disalin per blok dengan atomics dan smoothed values.
5. **In-Process VST3 Crash Vulnerability**:
   - *Masalah awal*: `PluginHostProtocol.h` hanya merupakan header kosong tanpa helper process yang berjalan, sehingga crash plugin langsung menjatuhkan mixer.
   - *Solusi*: Membangun executable terpisah `LiveBusPluginHost.exe` dengan Windows Named Shared Memory dan synchronisation events, disertai fallback dry audio real-time dan watchdog supervisor.

## Plugin Delay Compensation dan Recorder WAV

- PDC menggunakan latency yang dilaporkan oleh setiap chain VST3, menyelaraskan channel aktif terhadap chain channel paling lambat, lalu menyelaraskan Stream Bus, Monitor Bus, dan hardware direct output terhadap latensi bus terlama.
- Delay line multichannel dialokasikan saat audio device mulai, bukan pada callback. Perubahan delay memakai crossfade 128 sampel; permintaan di atas 65.536 sampel ditolak, jalur terkait kembali ke delay nol, dan aplikasi mencatat peringatan. Pastikan latency plugin yang dilaporkan sesuai dengan konfigurasi aktualnya.
- Recorder menghasilkan WAV stereo 24-bit dari Stream Bus setelah limiter keselamatan. Penulisan dilakukan oleh writer thread terpisah; jika antrean tulis penuh, blok yang terlewat dicatat dalam log. Perekaman otomatis dihentikan saat audio device berhenti atau aplikasi ditutup.
- Build dan tes otomatis tidak menggantikan uji perangkat audio, plugin VST3, durasi rekaman panjang, atau pemeriksaan output file pada mesin distribusi.
- Status startup perangkat/CPU kini menunggu telemetry aktual; daftar plugin bawaan yang sebelumnya menampilkan perangkat dan plugin contoh telah dihapus. Kontrol legacy scan/insertion pada rack utama masih belum terhubung ke enumerasi dan insertion engine, sehingga tidak boleh dianggap sebagai bukti plugin terpasang atau aktif. Ini terpisah dari engine VST3 dan helper IPC yang memiliki implementasi serta tes tersendiri.

## RNNoise VST3 dan batas validasi

- Gunakan `Effects` untuk memilih channel, lalu masukkan `LiveBus RNNoise` secara manual di rack. Plugin tidak diaktifkan atau dimasukkan otomatis, sehingga channel lain tetap tidak diproses.
- Pipeline RNNoise bawaan mixer dan fitur Auto Vocal Level/Auto Mixing sudah dihapus; tidak ada pemrosesan RNNoise ganda dari jalur internal aplikasi.
- Plugin menjalankan RNNoise secara lokal pada worker thread. Pemrosesan suppression memerlukan 48 kHz dan block maksimum 2048 sampel; pada konfigurasi yang tidak didukung, audio dilewatkan tanpa suppression. Tidak ada sample-rate conversion.
- Editor plugin menyediakan VAD enable, threshold, grace period, dan wet level. RNNoise dirancang terutama untuk speech-oriented noise suppression; hasil untuk singing dan musik harus diuji A/B karena dapat memengaruhi konsonan, napas, sustain, dan komponen tonal. Ini bukan pemisah sumber dan tidak menjamin penghapusan dengung/kipas.
- Latensi wrapper nominal adalah `2 x maximum block size + 480` sampel dan host memakai laporan latensi plugin untuk PDC. Angka ini bukan pengukuran latensi hardware/driver. Uji kualitas, latensi total, CPU, dan dropout dengan perangkat nyata masih diperlukan.
- AI Mixer Advisor, AI Assistant, dan Auto Vocal Level tidak lagi disertakan.

## Batasan Operasional yang Perlu Diketahui

1. **Virtual Audio Driver**:
   LiveBus Mixer adalah aplikasi audio tingkat pengguna (user-mode) dan sengaja tidak memaketkan driver kernel Windows virtual audio sendiri karena alasan stabilitas sistem dan persyaratan driver-signing Microsoft WHQL. Pengguna dapat mengintegrasikannya dengan virtual audio cable seperti VB-CABLE Driver Pack.
2. **Hardware Multi-Device Clock Drift**:
   Bila Stream Bus diarahkan ke Virtual Cable dan Monitor Bus diarahkan ke physical USB interface yang berbeda, perbedaan clock kristal dapat menyebabkan clock drift setelah berjam-jam pemutaran nonstop. Direkomendasikan menggunakan interface 4-out (Ch 1/2 Stream, Ch 3/4 Monitor) pada satu master clock untuk performa siaran tanpa henti.
3. **Physical MIDI Controller Testing**:
   Seluruh logika pemrosesan MIDI, Absolute/Relative translation, soft takeover pickup, filter channel/CC, Note toggle/momentary, Learn workflow, duplicate detection, dan preset XML telah diverifikasi melalui 9 automated test khusus. Pengujian dengan perangkat MIDI fisik (seperti Korg nanoKONTROL2 atau rotary encoder) bergantung pada ketersediaan hardware USB controller pada mesin pengguna. Sistem dilengkapi deteksi hotplug dan reconnect dinamis tanpa crash jika perangkat dicabut saat aplikasi berjalan.
4. **Playback Speed & Pitch Shifting Architecture**:
   Sesuai prinsip desain jujur (*no false claims*), kontrol Playback Speed (50% s.d. 200%) beroperasi menggunakan resampling rate berbasis `juce::ResamplingAudioSource`. Pitch shifting saat ini terhubung langsung ke rasio resampling (`semi = (speed - 1.0) * 12.0 st`) dengan indikator Lock aktif di UI. Algoritma phase-vocoder / time-stretch independen tidak diklaim secara palsu karena memerlukan alokasi buffer FFT berukuran besar dan latensi tambahan (~50-100ms) yang tidak real-time safe untuk live streaming broadcast tanpa engine WSOLA/elastique terdedikasi.
5. **Test Signal Generator Injection vs Physical Input Test**:
   Test Signal Generator menyuntikkan sinyal secara internal ke dalam DSP channel strip (Input 1-4) atau langsung ke Stream Bus / Monitor Bus master. Fitur ini dirancang khusus untuk menguji software DSP, gain staging, routing bus, dan transmisi virtual cable menuju OBS tanpa hardware loopback eksternal. Generator tidak dapat menguji microphone preamplifier atau converter ADC hardware fisik secara internal tanpa kabel loopback fisik nyata. Level generator dimulai pada default aman -24 dBFS dan selalu OFF saat startup guna melindungi pendengaran pengguna dan sistem monitor.
6. **VST3 GUI Editor Hosting & Generic Fallback**:
   Beberapa plugin VST3 pihak ketiga mungkin tidak menyertakan antarmuka kustom atau bergantung pada konteks grafis GPU proprietary tertentu. LiveBus Mixer secara otomatis mendeteksi ketersediaan custom editor: jika tersedia, jendela editor meng-host GUI native plugin; jika tidak tersedia atau gagal dibuat, engine secara otomatis menyajikan `juce::GenericAudioProcessorEditor` dengan parameter slider/toggle interaktif yang aman pada message thread. Jendela editor dikelola secara terpusat dan ditutup dengan aman saat instance dilepas untuk mencegah jendela editor yatim (*orphan windows*).
7. **Dual Hosting Modes & Latency Compensation**:
   LiveBus Mixer mengukur dan menampilkan latency samples aktual yang dilaporkan oleh masing-masing instance plugin pada insert rack slot dan total latency per target bus. Plugin Delay Compensation menyelaraskan seluruh jalur input/bus/direct hardware dengan delay line preallocated serta transisi delay bertahap. Mode In-Process memberikan zero IPC overhead dan latensi minimal, sedangkan Mode Out-of-Process (`LiveBusPluginHost.exe`) mengisolasi proses worker dengan circular shared memory buffer non-blocking pada audio callback (0ms wait) serta auto-recovery watchdog. Jika worker mengalami crash atau timeout, dry bypass seketika aktif tanpa mengakses pointer memori yang tidak valid.
